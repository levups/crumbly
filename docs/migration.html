Migration

Crumbly uses the same view helper names as these gems, so an app switches in one go. There is no compatibility layer, and the old gem leaves the Gemfile when the migration is merged.

  • From gretel
  • From breadcrumbs_on_rails
  • From loaf

From gretel

The idea stays the same: a crumb names its parent. The calls in your views barely change, and breadcrumb :order, @order and breadcrumb @order work as they did. What changes is config/breadcrumbs.rb, which becomes one class per namespace. A converter writes that class for you.

The two gems don't run side by side in production. gretel stays in the Gemfile of the migration branch only, for the comparison in step 2.

1. Convert the breadcrumbs file

bundle exec crumbly-convert config/breadcrumbs.rb --namespace Admin \
  --output app/breadcrumbs/admin/breadcrumbs.rb --views app/views/admin

This writes Admin::Breadcrumbs, then prints each thing it left out or couldn't convert exactly, with its line. You can pass several files (config/breadcrumbs/*.rb). They become one class, and when a crumb is defined twice the later one wins, as in gretel.

Some things are listed for you to convert by hand: a loop over anything but a literal array or hash of symbols, strings, numbers and constants; link or parent inside a loop or a block; link options such as title: or class:; a crumb named after a Ruby keyword or an existing method (display, test); and any statement that isn't a crumb, a loop or a local. Comments are kept, above the method they came before.

The converter needs Prism 1.2 or later. Ruby 3.4 comes with it. On Ruby 3.3, add gem "prism" to the development group.

2. Compare the trails

While gretel is still installed, your tests can draw every trail with both gems and list where the labels or URLs differ. Keep gretel in the test group with require: false. crumbly/oracle loads it without gretel's view helpers, whose breadcrumb would replace Crumbly's.

# Gemfile, on the migration branch
gem "gretel", require: false, group: :test

Your views already call breadcrumb the way Crumbly expects, so your controller, integration and system tests can do the comparing. With Crumbly::Oracle.watch in the test helper, gretel also draws each page the tests render, from the same breadcrumb call:

# test/test_helper.rb, once the app is loaded
require "crumbly/oracle"

Crumbly::Oracle.watch
Minitest.after_run do
  puts Crumbly::Oracle.differences.to_a, Crumbly::Oracle.redundant_calls.to_a
end

differences lists each page whose trail changed, with gretel's and Crumbly's side by side. It includes pages with no breadcrumb call, which had no trail with gretel and get one now. gretel shows a crumb's extra links as levels of their own, and the comparison does the same with links. A call that gretel can't draw is listed too, with gretel's error. redundant_calls lists the breadcrumb calls you can delete, because the page gets the same trail without them. watch { ... } watches a block only. Parallel test workers each keep their own lists, and after_run in the parent process doesn't see them, so run the watched suite with PARALLEL_WORKERS=1.

For crumbs that no test renders, compare checks the calls you give it:

class BreadcrumbsMigrationTest < ActionView::TestCase
  test "Crumbly draws the trails gretel drew" do
    differences = Crumbly::Oracle.compare(view, Admin::Breadcrumbs, [
      [:orders], [:order, orders(:alice)], [orders(:alice)], [:returns], [:returns, customers(:alice)]
    ])

    assert_empty differences, differences.join("\n")
  end
end

3. Review the calls in your views

The --views option of crumbly-convert lists the breadcrumb calls that Crumbly may now make unnecessary: :generic_form (or :new, :edit) in new and edit views, breadcrumb @order in a show view, and breadcrumb :orders in an index view. It doesn't delete anything. Remove a call once its page shows the same trail without it; for the pages your tests render, Crumbly::Oracle.redundant_calls tells you which ones. Area prefixes in crumb names (:admin_order) can go too, since the namespace keeps the areas apart.

4. Remove gretel

Remove gretel and config/breadcrumbs.rb, and render breadcrumb_trail in the layout where breadcrumbs was. The guide has a loop to start from. gretel's rendering options (style: :bootstrap5, the separator, link_current, semantic markup) become choices in your own markup, and its structured_data becomes breadcrumb_json_ld.

Then add the breadcrumbs test. It catches the parents, route helpers and view calls that the conversion got wrong, and the crumbs that nothing uses any more.

From breadcrumbs_on_rails

breadcrumbs_on_rails builds the trail in controllers. add_breadcrumb is called at class level, where a symbol path is called on the controller and only: and except: pick the actions, then inside actions. Each call adds a level after the last one. render_breadcrumbs draws the trail, with a separator: or a custom builder:.

Crumbly builds the trail from the other end. The view names its last crumb, and each crumb names its parent. Most add_breadcrumb calls go away, because index, show, new and edit get the same trail from the routes and the record the controller loaded.

breadcrumbs_on_rails

class Admin::OrdersController < Admin::BaseController
  add_breadcrumb "Home", :admin_root_path
  add_breadcrumb "Orders", :admin_orders_path

  def show
    @order = Order.find(params[:id])
    add_breadcrumb @order.to_s, admin_order_path(@order)
  end

  def messages
    @order = Order.find(params[:id])
    add_breadcrumb @order.to_s, admin_order_path(@order)
    add_breadcrumb "Messages", messages_admin_order_path(@order)
  end
end
<%= render_breadcrumbs separator: " / " %>

Crumbly

module Admin
  class Breadcrumbs < Crumbly::Trail
    def root
      crumb "Home", admin_root_path
    end

    def orders
      crumb "Orders", admin_orders_path
    end

    def order(order)
      crumb order.to_s, admin_order_path(order), parent: orders
    end

    def order_messages(order)
      crumb "Messages", messages_admin_order_path(order), parent: order(order)
    end
  end
end
<%# app/views/admin/orders/messages.html.erb %>
<% breadcrumb :order_messages, @order %>

index and show find these crumbs on their own. Without orders and order, they would still get "Orders" and the order's to_s

Steps

  1. Replace gem "breadcrumbs_on_rails" with gem "crumbly".
  2. The class-level "Home" becomes root in each namespace's trail class. A class-level section crumb ("Orders") becomes a crumb named after the controller, orders, but only if the label Crumbly would use (the model's plural name) isn't the one you want.
  3. Delete the add_breadcrumb calls in index, show, new and edit. For other actions, write a crumb and name it from the view with breadcrumb.
  4. Replace render_breadcrumbs with a loop over breadcrumb_trail. A custom builder becomes that loop, or your own component.

From loaf

loaf adds crumbs with breadcrumb, at controller class level (with only: and except:), inside actions, or in views. Its breadcrumb_trail passes each crumb to a block, with its name, url and current?. It decides current? by comparing the crumb's URL with the request (the match: option).

Crumbly uses the same two helper names, so loaf has to go first. In Crumbly, breadcrumb names one crumb instead of adding one, breadcrumb_trail returns an array instead of taking a block, and the current level is always the last one.

loaf

class Admin::CategoriesController < Admin::BaseController
  breadcrumb "Home", :admin_root_path
  breadcrumb "Categories", :admin_categories_path

  def show
    @category = Category.find(params[:id])
    @category.ancestors.each do |ancestor|
      breadcrumb ancestor.name, admin_category_path(ancestor)
    end
    breadcrumb @category.name, admin_category_path(@category)
  end
end
<% breadcrumb_trail do |crumb| %>
  <li><%= link_to crumb.name, crumb.url %></li>
<% end %>

Crumbly

module Admin
  class Breadcrumbs < Crumbly::Trail
    def root
      crumb "Home", admin_root_path
    end

    def categories
      crumb "Categories", admin_categories_path
    end

    def category(category, ancestors = category.ancestors.to_a)
      *grandparents, parent_category = ancestors
      crumb category.name, admin_category_path(category),
        parent: parent_category ? category(parent_category, grandparents) : categories
    end
  end
end
<% breadcrumb_trail.each do |level| %>
  <li><%= link_to_unless level.current?, level.label, level.url %></li>
<% end %>

show finds the category crumb on its own, so the view names nothing

Steps

  1. Replace gem "loaf" with gem "crumbly".
  2. Move the controllers' class-level crumbs into each namespace's trail class. "Home" becomes root, and a section becomes a crumb named after the controller.
  3. Delete the crumbs added in index, show, new and edit, and turn the others into crumbs that name their parent.
  4. In views, a run of breadcrumb "Name", path calls becomes one crumb method, named with breadcrumb :name.
  5. In the layout, breadcrumb_trail do |crumb| becomes breadcrumb_trail.each do |level|, and crumb.name becomes level.label.
