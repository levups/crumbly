Installation

# Gemfile
gem "crumbly"

There is nothing to configure: the gem adds breadcrumb, breadcrumb_trail and breadcrumb_json_ld to your views, and breadcrumbs_with to your controllers. It needs Ruby 3.3 or later and Rails 8.0 or later.

Writing crumbs

Crumbs live in a class that inherits from Crumbly::Trail. Every public method in it is a crumb. A crumb returns a label and a URL, and its parent if it has one, which is a call to another crumb. Rails loads the class like any other file in app/, so app/breadcrumbs/admin/breadcrumbs.rb defines Admin::Breadcrumbs.

# app/breadcrumbs/admin/breadcrumbs.rb
module Admin
  class Breadcrumbs < Crumbly::Trail
    def root
      crumb "Home", admin_root_path
    end

    def orders
      crumb "Orders", admin_orders_path
    end

    def order(order)
      crumb order.to_s, admin_order_path(order), parent: orders
    end

    def order_documents(order)
      crumb "Documents", nil, parent: order(order),
        links: [link("Invoices", admin_order_invoices_path(order)), link("Receipts", admin_order_receipts_path(order))]
    end
  end
end
<%# app/views/admin/orders/show.html.erb: optional, this is what the trail derives on its own %>
<% breadcrumb @order %>

In a view

  • breadcrumb :orders calls the crumb named orders. Its arguments come after the name: breadcrumb :order, @order.
  • breadcrumb @order calls the crumb named after the record's model, order for an Order. For a single-table inheritance subclass that has no crumb of its own, it uses the crumb of its parent class. A nil record, when the controller hasn't loaded @order, counts as an unknown crumb.
  • A view that calls neither gets a trail Crumbly works out on its own.

In a trail class

MethodWhat it does
crumb label, url = nil, parent: nil, links: []One level. url can be a string, a record or a polymorphic array such as [:admin, owner, :returns]. Leave it out for a level without a link. A javascript:, vbscript: or data: URL would run a script once your layout links it, so Crumbly refuses it, however it is spelled: see Crumbly::UnsafeUrl.
link label, urlAn extra link for links:, when a level points to more than one page.
crumb_for recordThe crumb of a record, found from its model. Use it when the parent can be one of several models.
helpersThe view, for view helpers such as helpers.t(".orders") or helpers.current_user.
rootYours to define. When it exists, every trail starts with it.

Private methods are helpers, not crumbs, so you can put shared code in them. Any public method can be called from a view, so Crumbly::Trail keeps its own methods private. Don't name a crumb crumb, link, crumb_for or helpers.

Rendering the trail

breadcrumb_trail returns the levels of the current page, from the root to the page itself. Each level has a label, a url (a path, or nil), its extra links (each with a label and a url), and current?, which is true for the last one. The gem writes no HTML for you. Whether the current page is a link, which separator to use and how to show extra links are up to your layout:

<%# app/views/layouts/admin.html.erb %>
<nav aria-label="Breadcrumb">
  <ol>
    <% breadcrumb_trail.each do |level| %>
      <li>
        <%= link_to_unless level.current?, level.label, level.url %>
        <% level.links.each do |link| %>
          <%= link_to link.label, link.url %>
        <% end %>
      </li>
    <% end %>
  </ol>
</nav>

Rails renders a view before its layout, so a breadcrumb call anywhere in the view runs before the layout reads breadcrumb_trail.

One trail class per namespace

Admin::OrdersController uses Admin::Breadcrumbs. If there is none, Crumbly looks in the enclosing modules, then for a top-level Breadcrumbs. An admin area and a storefront can each have an order crumb, and they don't clash.

A controller outside the namespace picks its class with breadcrumbs_with, and its subclasses inherit the choice:

class CheckoutController < ApplicationController
  breadcrumbs_with Storefront::Breadcrumbs
end

The classes live in app/breadcrumbs/, which Rails autoloads. With eager loading they are in memory before a prefork server forks.

Trails Crumbly works out on its own

When a view doesn't call breadcrumb, Crumbly builds the trail from the action:

ActionTrail
indexThe collection: your posts crumb if you wrote one, or else the model's plural name linked to the index route.
showThe record: your post crumb, or else its to_s linked to the show route, under the collection.
new, create"New" under the collection.
edit, update"Edit" under the record.

The record is the one the controller has already loaded, @post in PostsController. Crumbly never runs a query to find it, and without it show and edit get no trail. A controller with no index or show route still gets its level, without a link. Other actions get nothing.

Labels

"New" and "Edit" come from the crumbly.new and crumbly.edit translations:

# config/locales/es.yml
es:
  crumbly:
    new: Nuevo
    edit: Editar

Overrides

To change how these trails are built in a namespace, override any of four private methods in its trail class: collection_crumb, record_crumb(record), new_record_crumb and edit_record_crumb(record). The controller they read is private too.

module Admin
  class Breadcrumbs < Crumbly::Trail
    private

    def new_record_crumb
      crumb helpers.t("admin.breadcrumbs.new"), parent: collection_crumb
    end
  end
end

Nested routes

Under a nested route, each :<name>_id path parameter adds a parent level, outermost first. On /admin/posts/5/comments, the trail is Posts › Post 5 › Comments, and the post is the @post the controller loaded. Its level is your post crumb, or else its to_s linked to its show route.

If the controller didn't load a parent, Crumbly doesn't query it. It skips that level and the crumb named after the nesting, and keeps the parent's collection: Posts › Comments.

Which crumb wins

Crumbly takes the first of these that applies:

  1. The crumb the view names with breadcrumb.
  2. Your crumb named after the controller: posts in Admin::PostsController#index. Under a nested route it is named after the whole nesting and gets the parent records, so /admin/orders/42/messages calls order_messages(order). On show and edit, it is the crumb named after the record's model (post).
  3. The trail Crumbly works out. Its parent levels follow the same rule: your crumb for the parent's model if there is one, or else a level Crumbly builds.

Testing your trails

Add one test:

# test/breadcrumbs_test.rb
require "test_helper"
require "crumbly/test_helper"

class BreadcrumbsTest < ActiveSupport::TestCase
  test "breadcrumbs" do
    assert_breadcrumbs_valid
  end
end

It loads the whole app and reads the source of every crumb, and of the private helpers next to it, without running them or touching the database. It fails when:

  • a crumb's parent is not a crumb, or a _path or _url it calls is not a route helper;
  • a breadcrumb :name in app/views or app/controllers names a crumb that no trail class defines;
  • a view or another crumb calls a crumb with the wrong number of arguments. gretel ignored extra arguments and passed nil for missing ones, but a method raises ArgumentError. Calls spread over several lines, or with a splat, are skipped;
  • a crumb is never used. A crumb is used when another crumb, a view or a controller calls it (breadcrumb :name, breadcrumb @record), when a trail Crumbly works out reads it, or when it is named after a model.

A crumb defined twice in the same class is caught even earlier: the class raises Crumbly::DuplicateCrumb when it loads.

Outside Minitest, Crumbly.verify! runs the same checks. It raises Crumbly::InvalidTrail with every problem in one message, and returns the unused crumbs (["Admin::Breadcrumbs#drafts"]). Both accept trail_classes:, routes: and sources:, the directories it scans for breadcrumb calls.

Breadcrumbs for search engines

Google can show a page's trail in its results when the page describes it as schema.org structured data. Google needs absolute URLs, so use _url helpers in the crumbs of that namespace. They take the host from the current request.

module Storefront
  class Breadcrumbs < Crumbly::Trail
    def shop
      crumb "Shop", storefront_root_url
    end

    def category(category)
      crumb category.name, storefront_category_url(category),
        parent: category.parent ? category(category.parent) : shop
    end
  end
end

JSON-LD

breadcrumb_json_ld writes that description for the current trail. Put it in the <head>:

<%# app/views/layouts/storefront.html.erb, in <head> %>
<%= breadcrumb_json_ld %>
  • Positions start at 1. The last level may have no URL. A level above it without a URL isn't a page, so it is left out.
  • Names are plain text. If a label is html_safe (an icon, a <b>), its tags are removed.
  • The JSON is escaped for a <script> tag, so a label can't close it.
  • A relative URL raises Crumbly::RelativeUrl in development and test. In production it is reported to Rails.error and the page has no structured data. Crumbly.raise_on_relative_url changes this.
  • Crumbly::JsonLd.call(levels) returns the same data as a hash, if you build the structured data of the page yourself.

Errors

Every error is a Crumbly::Error.

ErrorWhen
Crumbly::DuplicateCrumbA trail class defines the same public method twice. It is raised when the class loads: at boot with eager loading, and in any test that loads the class.
Crumbly::UnknownCrumbA view names a crumb that doesn't exist, or breadcrumb @record or crumb_for finds no crumb for the record's model, or the record is nil. It is raised in development and test. In production it is reported to Rails.error, and the page renders without a trail.
Crumbly::MissingTrailA view reads the trail of a controller that has no trail class, found from its module or set with breadcrumbs_with. The message names the class to define.
Crumbly::InvalidTrailCrumbly.verify! found a crumb calling an unknown crumb or route helper, or a breadcrumb :name that no trail defines. The message lists every problem at once, and assert_breadcrumbs_valid turns it into a test failure.
Crumbly::RelativeUrlbreadcrumb_json_ld found a level whose URL is not absolute. It is raised in development and test. In production it is reported to Rails.error, and the page has no BreadcrumbList.
Crumbly::UnsafeUrlA crumb or a link gets a javascript:, vbscript: or data: URL, which a browser would run as a script, in any case and with spaces, tabs or control characters around it. It is raised in development and test. In production it is reported to Rails.error, and the level keeps its label without the link.

To choose when an unknown crumb, a relative URL or an unsafe URL raises, set it in an initializer:

# config/initializers/crumbly.rb
Crumbly.raise_on_unknown_crumb = true # on staging too
Crumbly.raise_on_relative_url = true
Crumbly.raise_on_unsafe_url = true
