Crumbly

Breadcrumbs for Rails.The line of links at the top of a page that shows where it sits in the site.

Each level of a trail, such as Home › Orders › Order 42, is a Ruby method that names its parent. On most pages you write nothing at all: Crumbly works the trail out from the controller and the routes. A test checks every trail before you ship.

gem "crumbly"

How it works

Add the gem (it needs Ruby 3.3 or later and Rails 8.0 or later), then write a class with one method per crumb. Each method returns a label, a URL and, if it has one, its parent. The layout loops over breadcrumb_trail and writes whatever HTML you like.

app/breadcrumbs/admin/breadcrumbs.rb

module Admin
  class Breadcrumbs < Crumbly::Trail
    def root
      crumb "Home", admin_root_path
    end

    def orders
      crumb "Orders", admin_orders_path
    end

    def order(order)
      crumb order.to_s, admin_order_path(order), parent: orders
    end
  end
end

app/views/layouts/admin.html.erb

<nav aria-label="Breadcrumb">
  <ol>
    <% breadcrumb_trail.each do |level| %>
      <li><%= link_to_unless level.current?, level.label, level.url %></li>
    <% end %>
  </ol>
</nav>

On an order page the trail is now Home › Orders › Order 42. A view can name its crumb with breadcrumb @order, but this one doesn't have to: a show page gets the trail of the record its controller loaded. The guide covers the rest.

What you get

A class per namespace

Admin::Breadcrumbs and Storefront::Breadcrumbs keep their crumbs apart, so both can have an orders crumb. Rails loads them like any other file in app/.

One trail class per namespace

Plain Ruby methods

A crumb is a method, and its parent is a call to another one. Route helpers work as they do in a view, and a backtrace points at the line that failed.

Writing crumbs

Trails you don't write

When a view names no crumb, the trail comes from the action, the routes and the record the controller loaded. Nested routes work too.

Trails Crumbly works out

Mistakes show up early

A crumb defined twice raises when the class loads. An unknown crumb raises in development and test. In production it is reported, and the page renders without a trail.

Errors

One test for every trail

assert_breadcrumbs_valid reads the source of every crumb. It fails on a parent or route helper that doesn't exist, on a view calling a missing crumb, and on a crumb nothing uses. It never touches the database.

Testing your trails

Your own HTML

breadcrumb_trail returns the levels, each with a label, a URL and current?. The gem has no styles or rendering options, so the markup is up to you.

Rendering the trail

Breadcrumbs in Google results

breadcrumb_json_ld describes the trail as a schema.org BreadcrumbList, which Google reads to show breadcrumbs in its results. A relative URL raises in development, before Google sees it.

Breadcrumbs for search engines

A converter from gretel

crumbly-convert turns config/breadcrumbs.rb into a trail class. While both gems are installed, your tests can compare the trails they draw. The migration guide also covers loaf and breadcrumbs_on_rails.

From gretel

Faster than gretel

A five-level trail renders as an <ol> in 45.4 µs, against 57.6 µs for gretel, with 274 allocations instead of 345 (YJIT off). The JSON-LD is a little slower, mostly because Rails' _url helpers are slower than _path ones.

Where it comes from

Crumbly started on a back office that used gretel: one breadcrumbs file of about 1,000 lines, with 265 crumbs and 380 calls in views. Everything lived in one global namespace, so the admin crumbs couldn't be kept apart from the storefront's, and a crumb defined twice silently replaced the first one. Mistakes only showed up when someone opened the page, and every trail was written by hand, even when the routes already said what it should be.

Crumbly keeps gretel's main idea, a crumb that names its parent, and writes it as plain Ruby. Here are five crumbs from that app in both gems.

Five crumbs in gretel and in Crumbly

gretel is on the left, in config/breadcrumbs.rb. Crumbly is on the right, in app/breadcrumbs/admin/breadcrumbs.rb.

A nested resource

gretel

crumb :order_messages do |order|
  link "Messages", admin_order_messages_path(order)
  parent :order, order
end

Crumbly

def order_messages(order)
  crumb "Messages", admin_order_messages_path(order),
    parent: order(order)
end

A polymorphic parent

gretel

crumb :returns do |owner|
  if owner
    link "Returns", [:admin, owner, :returns]
    parent owner
  else
    link "Returns", admin_returns_path
  end
end

Crumbly

def returns(owner = nil)
  return crumb("Returns", admin_returns_path) unless owner

  crumb "Returns", [:admin, owner, :returns],
    parent: crumb_for(owner)
end

A label computed from the record

gretel

crumb :order do |order|
  link "Order #{order.number}", admin_order_path(order)
  parent order.customer ? [:customer_orders, order.customer] : :orders
end

Crumbly

def order(order)
  crumb "Order #{order.number}", admin_order_path(order),
    parent: order.customer ? customer_orders(order.customer) : orders
end

A tree of categories

The ancestors are loaded once, in one query, and passed down the recursion.

gretel

crumb :category do |category, ancestors = category.ancestors.to_a|
  link category.name, admin_category_path(category)
  *grandparents, parent_category = ancestors
  parent_category ? parent(:category, parent_category, grandparents) : parent(:categories)
end

Crumbly

def category(category, ancestors = category.ancestors.to_a)
  *grandparents, parent_category = ancestors
  crumb category.name, admin_category_path(category),
    parent: parent_category ? category(parent_category, grandparents) : categories
end

A form

gretel: one generic crumb, called from every new and edit view

crumb :generic_form do |model|
  if model.new_record?
    link "New", nil
    parent model.class.model_name.plural.to_sym
  else
    link "Edit", nil
    parent model
  end
end
<%# app/views/admin/posts/edit.html.erb %>
<% breadcrumb :generic_form, @post %>

Crumbly

# Nothing to write: new and edit derive
# "New" under the collection,
# "Edit" under the record.
